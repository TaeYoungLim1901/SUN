## 지켜야 할 것 넷

**1. 규정이 우선이다.** `RULES.md` 와 다른 말을 하는 문서를 발견하면 그 문서가 틀린 것이다.
고치고 `POSTMORTEM.md` 에 기록해라.

**2. 문서를 크게 고쳤으면 검사를 돌려라.** 1초, 공짜다.

```bash
python tools/conform.py          # 되살아난 오류 검사
python tools/kit.py              # 채점기 자체 점검
```

**3. 새 실험 전에 `CLOSED_AXES.md` 를 사람이 직접 grep 한다.** 자동 중복 검사는 믿지 마라 —
지난 대회에서 닫힌 축을 5번 다시 열었다.

**4. 27일 재현성은 이번 대회에서 못 쓴다.** 제일 흔한 함정이라 여기에도 적는다.
입력 창이 120h 뿐이고 샘플에 날짜가 없다. 자세한 건 `DOMAIN.md` §9.1.

## 문서를 고치는 사람에게 (사람이든 에이전트든)

이 저장소의 실패는 거의 전부 **문서끼리 갈라진 것**에서 나왔다. 그래서:

- **숫자에는 출처를 붙인다.** 계산이면 계산식, 논문이면 쪽수. 못 대면 `[미검증]` 이라고 쓴다.
- **옛 값을 지우지 말고 `~~취소선~~` 이나 `[기록]` 으로 남긴다.** 왜 바뀌었는지가 다음 사람에게 필요하다.
- **한 곳을 고치면 그 값을 쓰는 다른 곳을 전부 찾는다.** `POSTMORTEM.md` 클래스 D 가 이걸 놓친 사례다.
- **위임한 수정은 diff 로 검토한다.** 요약 보고만 믿지 마라. 표면상 맞는 수정이 논리를 끊는 일이 실제로 세 번 있었다.

`AGENTS.md` 는 이 파일을 가리키고 **작업 절차(레포 둘·「작업 시작」)만** 추가로 담는다.
`CLAUDE.md` 는 `AGENTS.md` 를 가리키는 포인터일 뿐이다. **레포 설명은 여기 하나만 둔다** —
두 벌로 만들면 갈라지고, 갈라진 문서가 우리를 계속 물었다.
